# Running the advisor under different agent hosts

(To face an external agent as an *opponent* rather than host the advisor, see `docs/versus.md`.)

The harness is host-agnostic: everything an agent needs is a file in this
repository and every state change is a Python script. What differs per host
is only how the entry point and the procedures are discovered.

| Host | Entry point | Skills | Offline agents | Shell |
|---|---|---|---|---|
| Claude Code | `CLAUDE.md` imports `AGENTS.md` (`@AGENTS.md`) | read by path from `skills/` | `agents/*.md` via the Agent tool | Bash tool |
| Codex | `AGENTS.md` natively | read by path; `.agents/skills/` exposure is on the roadmap | `.codex/agents/*.toml` (generated by `scripts/sync_codex_agents.py`) | shell |
| OpenClaw | `AGENTS.md` in the agent's workspace | `<workspace>/skills/<name>/SKILL.md` — the same layout this repo uses | not used (single agent) | `exec` tool |
| Any other | read `AGENTS.md` first | `skills/*/SKILL.md` (Agent Skills frontmatter) | optional | needs a shell to run `scripts/*.py` |

## OpenClaw
OpenClaw agents live in a workspace directory that carries `AGENTS.md`,
`SOUL.md` and `USER.md`, load skills from `<workspace>/skills` (highest
precedence), and run commands with the `exec` tool. To make this repository
an OpenClaw workspace:

1. Point the agent's workspace at a clone of this repo
   (`openclaw.json` → `agents.entries.<id>.workspace`), or clone it inside
   the existing workspace and add a line to that workspace's `AGENTS.md`:
   "For Terraforming Mars, `cd marsmind` and follow its `AGENTS.md`."
2. Keep `SOUL.md`/`USER.md` as they are — `AGENTS.md` here only governs
   the game.
3. The skills in `skills/` are discovered as-is (each `SKILL.md` has the
   required `name`/`description` frontmatter). They are read-by-path
   procedures, not slash commands; the routing table in `AGENTS.md` decides
   which one applies.
4. Chat channel: a Telegram DM to the agent is the "player's words" channel
   of the physical or online mode — photos arrive as images, log lines as
   text. Nothing else changes.
5. Requirements on the host machine: Python 3.10+, this repo, and (mode 3
   only) Node for the local game engine.

Playing an online seat autonomously (the harness clicks for itself through
the app's API instead of advising a human) is a separate feature; see
`docs/ROADMAP.md`.
